# Understanding Success Criterion 2.2.1: Timing Adjustable

W3C's Understanding document for WCAG 2.2 success criterion 2.2.1, Level A.

## Summary

When content sets a time limit, users must be able to turn it off, adjust it, or extend it after a warning, so that people who read or act more slowly are not shut out. The document ranks the options: no time limit is better than an adjustable one, which is better than a request for more time. Exceptions cover real-time events, limits that are essential to the activity, and limits over 20 hours. Any automatic change after a set time counts as a time limit, including session timeouts.

## Why It Matters

Twice now: Thistlewood's 10-minute account timeout logged patrons out mid-hold ([[thistlewood-audit-report]]), and Tallowmere's 8-minute seat hold empties the basket without warning ([[tallowmere-seat-map-findings]]). Seat holds are a real constraint for a theatre, so the realistic fix is a warning with an extension, not removing the limit.
