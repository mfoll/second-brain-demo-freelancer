# Understanding Success Criterion 3.3.8: Accessible Authentication (Minimum)

W3C's Understanding document for WCAG 2.2 success criterion 3.3.8, Level AA, new in 2.2.

## Summary

Logging in to an existing account must not depend on a cognitive function test, such as remembering a password or transcribing a one-time code, unless an alternative method or a mechanism to help is available. Allowing password managers and paste into inputs is the usual way to meet it. Object recognition and recognising your own content are allowed at this level but discouraged. The criterion covers authentication of existing users, not account creation.

## Why It Matters

Copperline's sign-in blocks paste into the one-time code field and the password field, a security decision from years ago. Gideon Marsh asked me to review sign-in against this criterion if there is a phase 3 ([[should-i-propose-copperline-phase-3]]). It is the strongest argument for including sign-in in that scope.
